# n8n Connector — что видит и чем управляет пользователь после подключения

## 1. Целевой пользователь
Automation/ops-инженер, использующий self-hosted или n8n Cloud инстанс для связывания
внутренних сервисов workflow-автоматизациями (альтернатива Zapier/Make для тех, кто хочет
контролировать инфраструктуру сам).

## 2. Момент истины после подключения
Сразу после `connect_n8n` (с SSRF-защищённой валидацией self-hosted адреса) — список
workflows с их статусом активности (`list_workflows`) — сразу видно, что включено/
выключено, и что упало при последнем запуске.

## 3. Что пользователь видит
- Workflows целиком со всеми узлами (nodes) и связями — `list_workflows`, `get_workflow`.
- Историю выполнений workflow, включая ошибки — `list_executions`, `get_execution`.
- Учётные данные (credentials), настроенные в n8n, по названию/типу (без значений) —
  `list_credentials`.
- Активные webhook-триггеры — `list_webhook_nodes`.
- Теги, которыми организованы workflows — `list_tags`.

## 4. Чем пользователь может управлять
- Создавать/обновлять workflow программно (добавить узел, поменять связь) —
  `create_workflow`, `update_workflow`.
- Включать/выключать (publish/unpublish) workflow — `publish_n8n_workflow`,
  `unpublish_n8n_workflow`.
- Запускать workflow вручную с тестовыми данными — `execute_workflow`.
- Останавливать зависшее выполнение — `stop_execution`.
- Удалять workflow/execution — `delete_workflow`, `delete_execution`.
- Дублировать workflow как шаблон для нового процесса — `duplicate_workflow`.

## 5. "Вау"-момент для демо потенциальному клиенту
"Смотри — говорю Webbee: 'какие мои автоматизации сейчас выключены?'. Она находит через
`list_workflows`, а я прошу включить нужную — `publish_n8n_workflow` делает это без захода
в n8n UI, даже если инстанс развёрнут у меня на собственном сервере."

## 6. Что делает это "заточенным под него"
Работает с self-hosted инстансом клиента напрямую (с проверкой адреса от SSRF) — Webbee
не привязана к облачному n8n, видит ИМЕННО ту инфраструктуру, которую клиент сам поднял.
